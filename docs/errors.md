# Errors: where the TM goes wrong, and why

Generated by `codelangtm errors`; do not edit by hand. Machine-readable version: [errors.json](errors.json).

## Setup

- Every one of the 696 training snippets is predicted *out of fold*: by a model trained on the other 4 CV folds, which never saw it. The test set is not used.
- Models: `tm_400` (T=100, epochs=120, n_clauses=400, s=5.0, weighted_clauses=True) with seeds 1, 2, 3, 4, 5; baselines naive bayes, logistic regression, on the same folds.
- Consistency check: the per-fold macro-F1 of every model equals the `tm-results` run: **yes** (35 scores compared)
- Code of the misclassified snippets is not committed; `codelangtm errors` writes it, with the clauses that fired, to a local review file (`data/processed/errors-review.md`).

## Why do snippets fall into javascript?

52 of the TM's 178 errors (all seeds) predict javascript. Each hypothesis has a verdict rule fixed before the run, except H1's chance condition, added after seeing the data (see the note under the table).

| # | Hypothesis | Rule | Result | Verdict |
| --- | --- | --- | --- | --- |
| H1 | javascript really attracts the TM's errors | TM share above chance and above every baseline's | tm_400 (TM) 29%, naive bayes 19%, logistic regression 26% (chance 14%) | **supported** |
| H2 | Snippets that fall into javascript carry little evidence | fewer features present than always-right snippets, Mann-Whitney p < 0.05 | features (median) 72 vs 84; lines 29 vs 32; p = 0.095 | **not supported** |
| H3 | Errors into javascript are narrow wins | vote margin (predicted − true) smaller than other errors', Mann-Whitney p < 0.05 | median 70.5 vs 52 votes; p = 0.953 | **not supported** |
| H4 | javascript rejects other languages' code weakly | its mean vote total on other languages' snippets is the highest of all languages | javascript -175.5; highest: java -174.9 | **not supported** |
| H6 | javascript's signature n-grams are generic | its top-3 signature n-grams occur in other languages' snippets more often than any other language's do | javascript 30%; highest: java 36% | **not supported** |
| H7 | html snippets that the TM calls javascript are mostly embedded code | larger share of lines inside `<script>`/`<style>` than always-right html snippets, Mann-Whitney p < 0.05 | median 73% vs 5%; p = 0.004 | **supported** |

*Note on H1:* the first version of the rule only compared the TM with the baselines. For Python it passed although Python received fewer errors than chance, so the chance condition was added after seeing the data ([issues-and-fixes](issues-and-fixes.md) M11).

H7 in numbers: of 76 html snippets, 21 are more than half `<script>`/`<style>`; they are called javascript in 19% of predictions, against 0% for the other 55. Whether such snippets should be labelled html at all is the embedded-language policy planned for Stage B.
